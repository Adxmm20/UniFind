# UniFind agent notes

Single-page Next.js 16 (App Router), React 19, Turbopack. Styling is Material UI v9 + Emotion only — Tailwind was fully removed.

## Commands
- `npm run dev` — dev server on port 3000, host 0.0.0.0
- `npm run build` — production build (Turbopack)
- `npm run lint` — eslint (nextVitals + nextTs rules)
- `npm run db:seed` — create `data/unifind.db` from `db/schema.sql` + `db/seed.sql` using `node:sqlite` (no deps). **Non-destructive**: if the database already exists it is left alone, so accounts signed up at runtime survive.
- `npm run db:reset` — drop and recreate every table (`db:seed --force`). Use this when the schema/seed changes or you want a pristine database.

`predev`/`prebuild` run the non-destructive seed automatically. Because it now only seeds a missing database, a stale database is *not* repaired for you — run `db:reset` after editing `db/schema.sql` or `db/seed.sql`. Requires Node ≥ 22.5 (`node:sqlite`); developed on Node 24.

No test script, no CI workflows, no pre-commit hooks.

## Architecture (read before touching styling)
- `app/layout.tsx` — Server Component. Owns `<html>`/`<body>`, `metadata` export, `next/font` Geist, and wraps `{children}` in `AppRouterCacheProvider`. Must stay a Server Component: `metadata` cannot be exported from `"use client"`.
- `app/components/Header.tsx` — `"use client"`. Owns MUI `ThemeProvider` + `CssBaseline` + all UI (`AppBar`, `Drawer`, `TextField`, …). Direct child of `<body>` in layout. Takes `user: SessionUser | null`; when it is `null` the visitor is a **guest**, who browses the site exactly as usual but sees a guest drawer panel, no `Profile` link, and a `Bookmark` item that opens the login prompt. Signing in swaps the drawer summary to `MiniProfile` and reveals `Profile` + `Logout`.
- `lib/db.ts` — `node:sqlite` (`DatabaseSync`) singletons over `data/unifind.db` (override with `UNIFIND_DB_PATH`). `getDb()` is **read-only** and is all page rendering ever uses; `getWriteDb()` is read-write and is used *only* by the two things that write at runtime — auth (signup) and bookmark toggles. Server-only; never import from a client.
- `lib/auth.ts` — server-only auth. scrypt password hashing and a signed (`httpOnly`) session cookie via `node:crypto` — no runtime dependencies. `getSessionUser()` reads the cookie and resolves it against the DB; `authenticate` / `register` / `createSession` / `destroySession` do the rest. `SessionUser` is `{ email, username, phone }`, where `username` is the email local-part (same convention as `USERNAME_SQL` in `lib/queries.ts`).
- `app/actions/auth.ts` — `"use server"`. `loginAction` / `signupAction` / `logoutAction`, called directly from `LoginDialog.tsx` and `Header.tsx`. They return `AuthFormState` (`{ error, ok }`); the client shows `error` inline and the dialog closes itself once `ok` is true.
- `app/components/auth/LoginDialog.tsx` — `"use client"`. The one and only login/signup UI: a centred, desktop-style MUI `Dialog`, never a route. Split 35/65 — a solid theme-green (`#D8F3DC`) sidebar with the wordmark on the left, the stacked form on the right (bold `LOGIN` header, `variant="standard"` underline fields, a minimal underlined submit, the sign-up link, and the social row pinned bottom-right). Below `sm` the sidebar collapses and the card goes full-width. The view (Log in / Sign up) is controlled by `Header` so a trigger can pick it. `app/components/auth/GuestPanel.tsx` is the drawer summary shown to guests; `app/components/auth/SocialIcons.tsx` is the four black brand marks (Apple, Google, Facebook, TikTok) inlined as SVG — decorative, `aria-hidden`, and not focusable, because social sign-in is not wired up.
- `lib/queries.ts` — typed read helpers for every table (`getEvents`, `getRentals`, `getUserByUsername`, `getAllUsernames`, `getEventsByOrganizer`, `getItemsByProvider`, `getReviewsForProvider`, `getBookmarksForUser`, `getRsvpsForUser`, …). All synchronous, no ORM.
- `app/page.tsx` — Server Component. Reads events/items from SQLite via `lib/queries`, merges in local images from `public/img/` (`fs.readdirSync`), then renders `<Header />`, `<Slideshow />`, and a `<Suspense>`-wrapped Events/Rentals grid of `HomeTabs` `CardData`. The tabs are split: `app/components/HomeTabs.tsx` is the presentational bar+grid (also the prerendered Suspense fallback), and `app/components/HomeTabsUrl.tsx` reads/writes `?tab=` via `useSearchParams` (why the `Suspense` boundary is required). `app/components/ItemCard.tsx` renders a card, showing a blank placeholder when `image` is absent. The whole card stays clickable through a **stretched link** (`position:absolute; inset:0`) rather than a wrapping `<Link>`, which leaves room for the bookmark button as a *sibling* of that link — an `<a>` may not contain a `<button>`.
- `app/[username]/page.tsx` — Server Component dynamic route. Resolves the user by email local-part, then reads their events/listings/reviews. `generateStaticParams` prerenders all 17 usernames from the DB; unknown usernames render on demand and hit `notFound()`.
- `proxy.ts` — request-time Proxy (Next 16 defaults it to the Node.js runtime, so `node:sqlite` works). It runs *before* the render, so it can return a real **404** for unknown usernames by rewriting to `/__not-found__/404` (the page's own `notFound()` only yields a streamed 200 under PPR). Matcher skips `_next/`, `img/`, `bookmarks`, and dotted asset paths. Every *other* single-segment path is treated as a profile username, so **a new top-level route must be added to that pattern** or the proxy will look up a user of that name, fail, and rewrite the page to a 404.
- `app/not-found.tsx` — styled 404 (MUI + `Header`), rendered both by the proxy rewrite and by `notFound()`.
- `app/components/profile/` — `"use client"` profile UI (`ProfilePage`, `ProfileSidebar`, `ProfileTabs`); all data is passed in from the Server Component. `MiniProfile.tsx` (the `Header.tsx` drawer summary) shows the **signed-in** `SessionUser`, not the profile being viewed.
- `app/bookmarks/page.tsx` — Server Component. Guests get `BookmarksGuest` (a centred panel with its own `LoginDialog` instance); signed-in visitors get `BookmarksView`. Every card here is `bookmark: { signedIn: true, saved: true }`, since a row on this page is saved by definition.
- `app/components/bookmarks/BookmarksView.tsx` — `"use client"`. Owns the three toolbar controls: a pill `Select` filtering All/Events/Rentals, a second pill `Select` whose options **follow the filter** (only an event has a start time, only a rental has a price, so "All" offers just the keys both share), and an `IconButton` toggling grid/list. All three are local state, not URL params — the data is already loaded, so there is no round trip and no `Suspense` boundary (unlike `HomeTabsUrl`). A filter change that invalidates the current sort resets it in the change handler, never an effect. `app/components/ItemRow.tsx` is the list-view counterpart to `ItemCard`.
- `app/components/bookmarks/BookmarkButton.tsx` — `"use client"`. The bookmark control, **hidden until the card is hovered**: `opacity: 0` + `pointer-events: none`, revealed by `.MuiCard-root:hover &, .MuiCard-root:focus-within &`, and always visible under `@media (hover: none)` since touch has no hover state. `pointer-events` moves with `opacity` — an invisible button that still takes clicks is a trap sitting on top of the card. `focus-within` keeps it reachable by keyboard. A guest gets the same control with `signedIn: false`; clicking it raises the login prompt rather than writing.
- `app/components/auth/authPrompt.ts` — `"use client"`. `openAuthPrompt(tab)` dispatches a `unifind:auth-prompt` window event, which `Header` listens for. A bookmark button sits outside Header's subtree and `CardData` crosses the Server → Client boundary, so it can reach the dialog's state neither by props nor by callback; a window event is the smallest bridge that works without hoisting the dialog into a provider above the pages (see the gotcha below).
- `lib/bookmarks.ts` — server-only bookmark reads/writes. `getBookmarkIds(email)` returns a `Set` of record ids for a whole page in one query. `getBookmarkedEvents`/`getBookmarkedItems` are two joins (a row points at an event *or* an item) that also select `bookmark_id`, because `created_at` only resolves to the second and the id is the sole tiebreaker — the client sorts on the same pair so the merged "recently bookmarked" order matches the query's. `toggleBookmark` validates the target itself: `PRAGMA foreign_keys = ON` lives in `db/schema.sql` and applies only to the connection that ran it, so the write connection does **not** enforce the `REFERENCES`. There is no unique index on `(user_email, event_id)` — adding one means a schema change and `db:reset`, which would drop accounts created at runtime — so duplicates are cleaned up by the delete instead.
- `app/actions/bookmarks.ts` — `"use server"`. `toggleBookmarkAction(recordId)` reads the session and delegates to `lib/bookmarks.ts`, mirroring the auth split.
- `lib/images.ts` — server-only `listImages()` / `imageIndex()` (base name → public URL), shared by `app/page.tsx` and the bookmarks page so a card's picture resolves identically wherever it is rendered.
- `app/globals.css` — plain CSS variables + the wallpaper classes only. No `@import "tailwindcss"`, no `@theme inline`. Defines `--scroll-progress` (0 at the top of the page, 1 at the bottom) and the `--on-bg` / `--on-bg-muted` / `--on-bg-line` foregrounds that track it.
- `app/components/ScrollWallpaper.tsx` — `"use client"`, rendered once in `layout.tsx` as the first child of `<body>`, so every route shares it. Draws the fixed backdrop (`.scroll-wallpaper`, `z-index: -1`, behind all content) and, from a rAF-throttled scroll/resize/`ResizeObserver` handler, publishes `--scroll-progress` plus the interpolated `--on-bg*` colours on `<html>`. The CSS defaults equal the top-of-page state, so the server HTML and first client render match exactly — no hydration mismatch and no flash.

## Auth
- **Every demo account shares the password `unifind123`.** `db/seed.sql` stores a real scrypt hash (fixed salt, so the seed stays byte-for-byte reproducible). The `$2b$…` bcrypt strings that used to be there were truncated fakes and no account could log in.
- The login field accepts **either** the handle or the full email (`josa_organizer` or `josa_organizer@live.iium.edu.my`); an `@` picks the lookup. The handle shown in the UI is the email local-part.
- Handles are a login credential now, so `register()` rejects one that is already taken. Handles are derived from the email local-part rather than stored, so without that check two addresses (`a@x.com` and `a@y.com`) would share one and `getUserByUsername` would return either at random.
- `AUTH_SECRET` is read from the environment and signs the session cookie. There is a hard-coded development fallback so local work needs no setup — set a real `AUTH_SECRET` (e.g. in `.env.local`, which is gitignored) before deploying anywhere.
- Accounts live in the same `data/unifind.db`. Because seeding is non-destructive, they survive restarts; `npm run db:reset` wipes them.
- Lint enforces the React Compiler rule `react-hooks/set-state-in-effect`, so the login flow deliberately has **no effects**: `LoginDialog` calls the server actions from a submit handler and closes itself on success, and the controlled tab lives in `Header`. The one effect in `Header` is the `unifind:auth-prompt` listener, and it only calls its setters from inside an event callback, which the rule allows.

## Database merge (the dump in `db/unifind (2).sql`)
- The catalogue was merged **incrementally from a phpMyAdmin dump**, both into `db/seed.sql` and into the already-live `data/unifind.db`. It was never re-seeded: `npm run db:reset` would have dropped accounts created at runtime, so the merge was written as upserts on `event_id` / `item_id` plus inserts for new users. `bookmarks`, `event_rsvps` and `reviews` were left completely alone, and so were the two accounts the dump does not contain (`fawaz@gmail.com`, `marker_persistence_test@live.iium.edu.my`).
- Result: **27 users / 12 events / 18 items** from the dump, landing on 29 users live. The dump is authoritative for every field it carries. Where the two disagreed (event venue names, item locations) **the dump won**.
- Two field values are deliberately *not* copied verbatim, because the dump's are unusable: `users.password_hash` (truncated fake bcrypt — the seed writes a real scrypt hash instead) and the image columns (`events.banner_image_url` and `items.images` hold `example.com` URLs / JSON arrays in the dump; both DBs store the image stem instead, per the naming rule below).
- All 9 new items are `item_type='service'` and are named `service-<n>` in `public/img/Services/`, distinct from the `item-<n>` rentals in `public/img/Rental/`. Their record id is still `item-<n>` — the *stem* is what differs, not the id.
- **Outstanding:** the merge is done and verified at the database and image level, but services are still invisible in the UI. `getRentals()` filters `item_type='rent'`, `HomeTabs` only has Events and Rentals, and `BookmarksView` has no Services filter, so nothing reads the 9 service rows yet. Surfacing them needs `getItems()` (which exists — the details page already uses it) wired into `app/page.tsx` and the bookmarks page, a third tab, and a third filter entry.

## Hard-learned gotchas (these caused real build/runtime errors)
- MUI styling is Emotion-based; it **requires** `<AppRouterCacheProvider>` (from `@mui/material-nextjs/v16-appRouter`) wrapped around `{children}` in `layout.tsx`. Without it, Emotion injects inline `<style data-emotion>` tags into `<body>` during SSR and React throws "Hydration failed because the server rendered HTML didn't match the client". Keep the package version in lockstep with `@mui/material` (both `9.5.0`).
- Do **not** insert an intermediate `"use client"` wrapper (e.g. a `ThemeProvider` component) between `layout.tsx` and `page.tsx`. Passing a MUI theme object across the Server → Client boundary during static prerendering causes "multiple renderers" / "Unexpected Fiber popped" errors. Keep `ThemeProvider` inside `Header.tsx`, directly under `<body>`.
- Do **not** call hooks at module scope in a Client Component (`useMemo` at file level threw "Invalid hook call"). `createTheme()` at module scope is fine — no hook needed.
- No `tailwind.config.js` ever existed (Tailwind v4 configured via CSS import). Do not re-add `@import "tailwindcss"` or Tailwind utility classes; the build has no Tailwind loader.
- MUI v9 removed the deprecated **system props** from components. `alignItems`, `justifyContent`, `mb`, `display`, etc. are **not** valid direct props (TS error: "Property 'alignItems' does not exist on type … StackOwnProps"). Put them in `sx` instead: `<Stack direction="row" spacing={1} sx={{ alignItems: "center" }}>`. Component-owned props still work directly (`direction`/`spacing` on Stack, `variant`/`color` on Typography, `underline` on Link).
- MUI v9 also renamed the internal classes the docs and Stack Overflow answers use. `Tabs` renders `MuiTabs-list`, **not** the old `MuiTabs-flexContainer`, so `sx={{ "& .MuiTabs-flexContainer": … }}` silently does nothing. Reach for `.MuiTabs-list` to style the tab strip. (`centered` + `variant="scrollable"` is still a rejected combination that warns, hence centring through the list class.)

- `export const dynamicParams` is **not allowed** with `cacheComponents` (build error: `Route segment config "dynamicParams" is not compatible with nextConfig.cacheComponents`). Without it, unknown dynamic params render on demand; use `proxy.ts` when you need a real 404 status.
- Reading the session cookie makes a route dynamic, and `cacheComponents` refuses to prerender it (build error: `Next.js encountered uncached or runtime data during prerendering`). The fix lives in **one place**: `app/layout.tsx` exports `instant = false`, which opts the whole app into blocking dynamic rendering instead of streaming. Put it there and not on individual pages — `app/not-found.tsx` is a special file that cannot declare its own segment config, so the `/_not-found` route only passes because the root layout covers it. Every route now reports as `ƒ (Dynamic)`; this is the deliberate trade-off for having the correct guest/signed-in state in the first paint rather than flashing a guest UI. (The alternatives are wrapping the header in `<Suspense>`, or reading the session client-side after mount.)
- `notFound()` reached after PPR/streaming has started keeps the response at **200** (Next adds `<meta name="robots" content="noindex">`). For a real 404, run the check before the render — i.e. in `proxy.ts`.
- MUI's polymorphic `component` prop takes a *function*, which cannot cross a Server → Client boundary (`Functions cannot be passed directly to Client Components`). In a Server Component prefer MUI's native `href` (renders an `<a>`) or `next/link`; do not use `component={Link}`.
- `@types/node` must stay at `^24` — the `node:sqlite` types (`DatabaseSync`) do not exist in older versions.
- Anything rendered **directly on the page background** (i.e. not inside a `Card`, the drawer, or the `AppBar`) must use `var(--on-bg)` / `var(--on-bg-muted)` / `var(--on-bg-line)` for its colours — not `#081C15`, `text.primary` or `text.secondary`. The wallpaper fades to deep forest green as you scroll, so hard-coded dark colours vanish near the bottom. Text inside `ItemCard` (and the drawer/AppBar) deliberately keeps its normal dark-on-light colours because those sit on their own surfaces.
- Page content renders **outside** `Header`'s `ThemeProvider` — the provider is scoped to Header's own subtree — so anything using MUI palette defaults on a page falls back to the **stock MUI theme**, not the site colours. An unstyled `variant="contained"` button comes out MUI blue and a focused `TextField` underlines in blue. `BookmarksGuest`'s button and `LoginDialog`'s focus colours are pinned explicitly for this reason (and because `LoginDialog` is rendered from two places, only one of which is inside the provider). Pin the colour whenever a page-level component must match the palette.

## Verifying SSR style placement
All `data-emotion` `<style>` tags belong in `<head>`, and **zero** in `<body>`. A body-level `data-emotion` tag means the Emotion cache is misconfigured.

The old way to check this — reading `.next/server/app/index.html` after a build — no longer works: with `instant = false` every route is dynamic, so that file (and `bookmarks.html`, etc.) is written **0 bytes** and the check silently passes on nothing. Check the live server instead:

```powershell
node -e "fetch('http://localhost:3000/').then(r=>r.text()).then(h=>{const b=h.slice(h.indexOf('<body'));console.log('body data-emotion:',(b.match(/data-emotion/g)||[]).length)})"
```

Also watch the browser console for `Hydration failed` / `did not match` while loading the pages — that is the symptom the placement rule prevents.

## Paths / imports
- `@/*` maps to repo root (tsconfig `paths`).
- Slideshow images live in `public/img/trending/` and are auto-discovered at build time: `app/page.tsx` (Server Component) reads the folder with `fs.readdirSync` and passes `Slide[]` (`{ id, href, src }`) to `<Slideshow slides={...} />`. Drop a new image in `public/img/trending/` (no code change) — the count drives nothing but how many dots the window scrolls through. In `next dev` new files appear on refresh; production needs a rebuild.
- **`Slideshow.tsx` is a coverflow stage, not a 3D ring.** The active slide sits flat in the middle; its two neighbours lean away from the camera (a plain `rotateY` about each panel's own centre, so the browser's perspective projection does the widening/narrowing) and every other slide waits further out at `opacity: 0` — that parked position is what makes a change animate instead of snap. **The lean points away from the middle**, so the neighbours' *inner* edges (the ones beside the arrows) are the tall, close ones and their outer edges fall away small: that is the deliberate reverse of the classic coverflow look. Flipping the sign is a one-character change in `coverflowTransform`, but be aware it moves everything else too — with the panels facing outward the far edge recedes, which pulls the silhouette *inward*, so the same constants give a much smaller overhang off the screen edge and a gap between the arrow and the panel. The direction was re-tuned after the flip (`TILT_DEG`/`SIDE_SCALE`/`SIDE_SHIFT`) to buy the overhang back.
- Frames and dots use `FRAME_COLOR`, which copies the header's AppBar neutral (`color="default"` → MUI `grey[100]`, `#F5F5F5`) rather than a hard-coded black. Keep them in step if the AppBar colour ever changes. The dots are a hair lighter than the wallpaper's top gradient, so their `boxShadow` is what actually gives them an edge — do not drop it.
- Two couplings matter in the stage: the section is deliberately **full bleed** (`overflow: hidden`, no `maxWidth`) because the neighbours have to run off the screen edges — do not slot it back into the 1400px content column the rest of the page uses; and `SIDE_SCALE` is what keeps the neighbours inside the stage. With the lean pointing outward the magnified corner is the **inner** one, so the ceiling is `PERSPECTIVE / (PERSPECTIVE - sin(TILT) * w * S / 2) < 1 / SIDE_SCALE` — that is why `SIDE_SCALE` cannot go much above 0.9, and why widening the `clamp()` ceiling for `--slide-w` without lowering it starts clipping the tall inner edges against the stage's top and bottom. The `layout-check` helper measures this directly as `clipped`. Because the slides are `position: absolute` inside the stage (not children of a transformed ring), `pointerEvents` is switched off for the off-stage ones — an invisible panel that still takes clicks is a trap sitting over the frame.
- Items and events were merged from a phpMyAdmin dump (`db/unifind (2).sql`) — see the **Database merge** section above.
- `data/unifind.db` is generated by `npm run db:seed` and gitignored (`/data/*.db`). `next.config.ts` sets `outputFileTracingIncludes: { "/**": ["./data/**"] }` so the standalone output ships it. Seeding is non-destructive, so this file is *not* rebuilt on every `dev`/`build` — `npm run db:reset` is the explicit rebuild.
- **Header logo.** `Header.tsx` renders `public/img/logo-wordmark.png` (the `UniFind` wordmark with a magnifying glass for the `d`) at a fixed 32px height, linked to `/`. That file is a **cropped derivative** of `public/img/logo.png`: the original is 604×478 but the actual wordmark ink is only 457×157, so rendering it directly at header height would make the text illegibly small. `logo.png` is kept untouched; regenerate the crop with `System.Drawing` if the wordmark changes.
- **Image naming is the identifier.** Every event/item has a canonical record id `<kind>-<n>` (`event-1`, `item-4`), and its picture is named after that stem: `public/img/Events/event-1.jpg`. `events.banner_image_url` and `items.images` store the stem (`'event-1'`, `'item-4'`) and each page builds a `stem -> URL` index (`imageIndex(folder)`) so it looks rows up **by name** — inserting or reordering rows can never shift which picture a card gets. Items sit in a folder chosen by type, so a rental is `item-<n>` in `public/img/Rental/` but a service is `service-<n>` in `public/img/Services/`; both pages resolve items through `itemImageIndex()`, which merges the two folders into one stem index. A row whose stem has no file renders the blank placeholder. Text-image order and `public/img/*.png` (legacy) are no longer used.
- `app/details/[id]/page.tsx` — placeholder Details route keyed by the record id (`/details/event-1`, `/details/item-4`). It prerenders every known record id (events via `getEvents()`, plus **all** items via `getItems()` — services included, since `getRentals()` alone would leave them as on-demand params) via `generateStaticParams` (without it, the DB read blocks prerendering under `cacheComponents`). Real details content is still to be built.
- MUI theme background colors: `#D8F3DC` (default/paper), primary `#081C15`. Typography references `var(--font-geist-sans)`.
